# Roadmap

The near-term priority is physical Rev C Prototype #1 evidence. See the detailed
[hardware evidence roadmap](../../hardware/rev_c/ROADMAP.md).

1. Assemble, power, and characterize Rev C without advancing maturity by prose.
2. Refine Rev C only when measured evidence identifies a defect or trade-off.
3. Build multi-node experiments with ESP-NOW; evaluate correlation only with real timestamps and measurements.
4. Consider an external LoRa-class transport only after its protocol, power,
   coexistence, and legal requirements are defined.
5. Keep 5.8 GHz analog-video and CVBS work as separate experiments.
6. Consider TinyML only with a real dataset, reproducible training, a model,
   metrics, and physical validation.
7. Consider Mini or Rev D only when evidence demonstrates a concrete need.

No public roadmap item is a current capability claim.
